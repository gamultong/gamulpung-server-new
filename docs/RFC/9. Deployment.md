# 9. Deployment

이 문서는 Gamulpung Server의 배포 전략을 정의합니다.

## 용어 정의
- **Environment**: 배포 대상 환경. development(개발), production(프로덕션)으로 구분됩니다.
- **Deployment**: 빌드된 Docker 이미지를 서버에 배포하는 과정입니다.
- **Release Tag**: 프로덕션 배포를 트리거하는 Git 태그. `v*.*.*` 형식의 Semantic Versioning을 사용합니다.

## Introduce

개발 환경과 프로덕션 환경을 분리하여 안정적인 배포 프로세스를 구축합니다.
개발 환경에서 충분한 테스트를 거친 후 프로덕션 배포를 진행하여 서비스 안정성을 확보합니다.

배포는 브랜치와 태그 기반으로 자동화되며, 각 환경은 GitHub Environments로 관리됩니다.

## Deployment Strategy

### Development Deployment
`develop` 브랜치에 push되면 development 환경으로 자동 배포됩니다.
Docker 이미지는 `:dev` 태그로 빌드됩니다.

### Production Deployment
`v*.*.*` 형식의 태그를 push하면 production 환경으로 자동 배포됩니다.
Docker 이미지는 `:latest`와 `:v1.0.0` 두 개의 태그로 빌드됩니다.

**제약사항:**
- Release Tag는 반드시 `main` 브랜치에서 생성되어야 합니다.
- 다른 브랜치에서 태그를 생성하면 배포가 실패합니다.
- `main` 브랜치는 protected branch로 설정하여 직접 push를 방지해야 합니다.

## GitHub Environments

GitHub Environments를 사용하여 development와 production 환경을 분리합니다.
각 환경은 독립된 Secrets를 가지며, 동일한 이름으로 관리됩니다.

### Repository Secrets (공통)
Docker Hub 접근을 위한 공통 Secrets입니다.
- `DOCKER_USERNAME`
- `DOCKER_PASSWORD`
- `DOCKER_REPONAME`

### Environment Secrets (development/production 각각 설정)
각 환경마다 다음 Secrets를 설정해야 합니다.
- `DOTENV`: 환경변수 파일 내용
- `HOST`: 서버 주소
- `SSH_USERNAME`: SSH 사용자명
- `SSH_KEY`: SSH 개인키
- `SSH_PORT`: SSH 포트
- `CONTAINER_NAME`: Docker 컨테이너명
- `CONTAINER_PORT_MAPPING`: 포트 매핑 (예: `8080:8000`, `80:8000`)

## Deployment Flow

### Development
```
feature 브랜치 작업
  ↓ PR
develop 브랜치 merge
  ↓ 자동 트리거
Docker 이미지 빌드 (:dev)
  ↓
development 환경 배포
```

### Production
```
develop 브랜치 테스트 완료
  ↓ PR
main 브랜치 merge
  ↓ 검증
Release Tag 생성 (v1.0.0)
  ↓ 자동 트리거
Docker 이미지 빌드 (:latest, :v1.0.0)
  ↓
production 환경 배포
```
