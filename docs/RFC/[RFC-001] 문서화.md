이는 RFC 및 기타 문서 작성에 관한 가이드 입니다.

## 개요
모든 구현 및 논의의 문서가 필요하지 않습니다.
문서는 사용되어야 하며, 행위의 결과만 작성되어야 합니다.
사용되지 않으며, 행위의 결과가 아닌 것은 문서로 작성되지 않으며, 이는 기록됩니다.(ex. issue, commit 등)

## 종류
문서는 다음과 같은 종류가 있습니다.
- RFC : 프로젝트 전반에 적용되는, 컨셉 및 논의 결과
- ADR : 논의나 결정의 대하여 의사의 흐름을 기록
- API spec : API에 대한 spec
이는 추가, 변경 될 수 있습니다.

## 작성 가이드
### 문체
문서는 한글 작성을 전제합니다.
단 프로젝트에서 사용되는 용어는 원문 그대로 작성해 주세요.
용어는 반드시 `Glossary/`에 등록되어야 합니다.

문장은 존대를 기본으로 작성 합니다. 그러나 `:`, `=`와 같이 대입 표현의 관하여 존대를 사용하지 않습니다.

### 문서 작성
#### RFC
RFC에는 결과 위주로 작성합니다.
될 수 있다면 간결하게 작성해 주세요.
ex) "A를 사용함" O, "B같은 이유 때문에 A를 사용함" X

결과가 아닌 목적이나, 사유, 판단 및 근거는 ADR를 작성 후 ref를 달아주세요.
##### 형식
파일 이름은 다음과 같은 형식을 가집니다.
`[RFC-{number}] {subject}`
- number : RFC 문서의 식별자. 3자리 숫자
- subject : RFC 문서 작성 주제

문서 작성 양식은 크게 정해져 있지 않습니다.
자유롭게 작성하되, 제목 아래 문서 작성 목적을 제시해야 합니다..
```md
문서 작성 목적

... 본문
```

#### ADR
ADR는 목적이나, 사유, 판단 및 근거를 작성합니다.
##### 형식
파일 이름은 다음과 같은 형식을 가집니다.
`[ADR-{number}] {subject}`
- number : ADR 문서의 식별자. 3자리 숫자
- subject : ADR 문서 작성 주제

문서의 형식은 다음과 같습니다.
```md
문서 작성 목적

## Context
배경 및 제약사항

## Decision
결정

### Alternatives Considered
대안

## Consequences
결과 및 영향
```

#### 기타
`module`의 `docs/`를 참조하려면 `Referece`에 추가하세요.
주위 할 점 -> link를 걸면 OS 호환 문제가 생길 수 있습니다.

이는 Window 기준으로 다음 명령어를 입력하면 됩니다.
`mklink /J <생성 위치> <소스 위치>`

#### 링크 전략
문서 간 링크는 다음 규칙을 따릅니다:
- Module 내 docs 참조: 상대경로 사용
- 프로젝트 전반 문서: 절대경로 사용

자세한 내용은 [ADR-001](/docs/ADR/%5BADR-001%5D%20상대경로%20링크%20채택.md)를 참조하세요.
