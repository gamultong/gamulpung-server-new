# Coding Convention

## 목적
코드 전반에 일관되게 적용하는 작성 규칙을 정의한다. 이미 코드베이스에 정착된 관례를 명문화한 것이다.

## 규칙

### 명명
- 함수·변수·모듈은 snake_case, 클래스는 PascalCase를 따른다.
- 이벤트 이름은 대문자+하이픈 규칙을 따르며 메커니즘으로 강제된다. ([명명 규칙](/docs/Other/API_spec/WebSocket/README.md))
- python 내장 이름(id, range, dict 등)을 가리는 작명은 피한다.

### Type Hint
- 모든 함수 시그니처에 파라미터와 반환 타입을 명시한다.
- 문자열로 타입을 명시하지 않는다. 순환 참조는 future annotations와 TYPE_CHECKING 조합으로 해결한다.
- Optional 표기 대신 `X | None` 표기를 사용한다.
- 제네릭을 활용해 구조를 타입으로 드러낸다 (예: Event의 payload 타입 파라미터).

### 주석·문서화
- 주석과 docstring은 한국어로 작성하고, 코드가 바뀌면 함께 갱신한다.
- 불변식 검사나 비자명한 분기 직전에는 사유를 주석으로 남긴다.
- 주석 처리된 죽은 코드를 남기지 않는다.

### 로깅
- loguru를 사용하며 메시지는 f-string으로 보간한다. % 스타일 포맷은 인자가 유실되므로 금지한다.
- 메시지는 한국어로 쓰고 '사유 | key:value' 형태로 컨텍스트를 붙인다.
- 레벨 관례: 거부·무시된 입력은 warning, 흐름 추적은 debug, 복구 불가 상황은 error.

### 예외
- 의미 있는 예외 타입을 사용한다. 문자열 raise와 bare except는 금지한다.
- 발생 가능한 외부 입력 오류는 가드절(경고 후 조기 반환)로, 코드 불변식 위반은 예외로 구분해 처리한다.

### 강제 수단
- lint는 ruff를 사용하며 CI가 게이트한다. 로컬에서는 make lint로 실행한다.

## 적용 범위
프로젝트 전체 소스 코드에 적용된다.
