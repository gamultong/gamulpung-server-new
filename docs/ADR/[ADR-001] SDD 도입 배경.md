# SDD 도입 배경

## 상황
문서가 방대해지고, 코드와 문서가 불일치하며, 개발자·에이전트 간 의도 해석 차이가 발생하는 문제를 해결할 필요가 있었다.

## 결정
프로젝트 전반에 Spec Driven Development(SDD)를 도입한다. ([[RFC-001] SDD](/docs/RFC/%5BRFC-001%5D%20SDD.md))

## 근거(요약)
- 문서와 코드의 이중 관리 비용 제거가 필요함.
- 문서의 최소 유지 및 재사용이 가능한 구조가 필요함.
- 의미적 스펙을 명확히 남겨 개발자·에이전트 협업 정확도를 높여야 함.
