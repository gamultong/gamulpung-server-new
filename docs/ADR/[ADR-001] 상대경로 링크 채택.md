문서 링크 전략에 대한 의사결정

## Context
Gamulpung Server 프로젝트는 다음과 같은 문서 관리 요구사항을 가지고 있습니다:
- GitHub에서 문서를 읽을 때 링크가 정상적으로 작동해야 함
- Obsidian을 사용한 문서 관리 및 탐색이 가능해야 함
- Module 분산 구조 (handler/docs/, core/docs/ 등)에서 각 모듈의 독립성 유지

이러한 요구사항을 만족하는 링크 전략이 필요했습니다.

## Decision
문서 링크는 참조 대상에 따라 다음과 같이 구분하여 사용합니다:

1. **Module 내 docs 참조**: 상대경로 사용
   - 예: `/docs/README.md`에서 handler 문서 참조 시 `[handler docs](../handler/docs/README.md)`

2. **프로젝트 전반 문서 참조**: 절대경로 사용
   - RFC 문서: `[Architecture](/docs/RFC/1. Architecture.md)`
   - API spec: `[MOVE API](/docs/API_spec/WebSocket/Client/MOVE.md)`
   - ADR: `[ADR-001](/docs/ADR/[ADR-001] 상대경로 링크 채택.md)`

## Alternatives Considered

### 1. 완전 상대경로
모든 링크를 상대경로로 작성하는 방식
- 장점: 저장소 경로 독립적
- 단점: 복잡하고 유지보수 어려움. 파일 위치 변경 시 많은 링크 수정 필요

### 2. 완전 절대경로
모든 링크를 절대경로로 작성하는 방식
- 장점: 명확하고 단순함
- 단점: Module 재배치 시 모든 링크가 깨짐. Module 독립성 저해

### 3. Obsidian 위키링크
Obsidian의 `[[문서명]]` 형식 사용
- 장점: Obsidian에서 편리한 탐색
- 단점: GitHub에서 링크가 작동하지 않음

## Consequences

### 긍정적 영향
- ✅ GitHub와 Obsidian 양쪽에서 모두 링크가 정상 작동
- ✅ Module별 독립성 유지 가능
- ✅ 프로젝트 전반 문서는 어디서든 일관된 방식으로 참조 가능

### 부정적 영향
- ⚠️ 두 가지 링크 규칙을 숙지해야 함
- ⚠️ 새로운 문서 작성 시 올바른 링크 형식 선택 필요

### 완화 방안
- RFC-001 문서화 가이드에 링크 전략 명시
- 문서 리뷰 시 링크 형식 검증
