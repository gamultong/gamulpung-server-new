# 데이터 정합성 수준 채택

## 상황
다단계 쓰기의 트랜잭션 경계와 Event 처리 실패의 복구 수준을 정해야 했다. 저장소는 함수 호출 단위로 commit하며, Event 처리 실패에 대한 재시도·보상 처리는 없다.

## 결정
Handler·Receiver 실행을 원자성 단위로 보고, 그 이상의 트랜잭션 경계나 Event 실패 복구 장치를 두지 않는다. 실패 격리의 기준은 "실패가 새로운 Event를 만들지 않는 것"이며, 예외가 진행 중인 실행 scope(호출 체인) 안에서 전파되는 것은 허용한다.

## 근거(요약)
- 실패가 추가 Event를 발행하지 않는 한 시스템은 오염되지 않는다. 상위로 번지는 복구 흐름은 복잡성만 키운다.
- 게임 도메인 특성상 강한 데이터 정합성이 필수적이지 않다.
- 단순성을 우선한다. ([원문 답변](/docs/Other/Design%20QnA%202026-06.md))
