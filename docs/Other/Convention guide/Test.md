# 테스트 작성 가이드

## 배치
- 모듈 단위 테스트는 해당 모듈의 test/ 디렉토리에 둔다. ([[RFC-003] Module](/docs/RFC/%5BRFC-003%5D%20Module.md))
- 기능 통합 테스트는 tests/integration에 두고 FT 문서 번호와 1:1로 매핑한다.
- FT 문서는 대응하는 테스트 파일을 인라인 링크로 참조한다.

## 명명
- 통합 테스트 함수명은 FT 문서의 3개 섹션(시나리오, 비즈니스 규칙, 상태 변화)에 대응하는 접두를 사용한다.
- 테스트 docstring과 assert 메시지는 한국어로 쓰고, 검증하는 FT 문서 내용을 인용한다.

## 작성
- 보드 상태는 문자 그림 기반 빌더(ASCII 맵 DSL)로 선언해 의도를 시각적으로 드러낸다.
- 이벤트 수신은 폴링 대기 헬퍼로 검증한다. 고정 시간 대기는 금지한다.
- 이벤트는 payload까지 완전 매칭으로 검증한다. 이벤트 종류만 확인하는 것은 완료 대기 용도로만 쓴다. ([상세 가이드](/tests/integration/GUIDELINES.md))
- 부수 효과 이벤트를 모두 소비한 뒤 다음 시나리오를 진행한다.

## 격리
- 테스트는 임시 파일 DB와 핸들러 상태 초기화(autouse fixture)로 서로 격리된다.
- 테스트 실행이 git 추적 파일을 변경해서는 안 된다.

## 실행
- 전체 테스트는 make test-all 단일 진입점으로 실행하며, CI와 로컬이 동일한 명령을 쓴다.
