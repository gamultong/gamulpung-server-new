# Feature(FT) 작성 가이드
- `docs/Feature/`에 저장한다.
- 파일 이름은 `[FT-XXX] Title`의 형태로 작성한다.
- 도메인 관점에서만 서술한다 (UI/Transport/이벤트명 등 구현 용어 금지).
- API spec, RFC, 테스트 코드 링크는 인라인으로 배치한다.

## 형식
```md
# 기능명

## 시나리오
"누가/언제/무엇을/왜" 중심의 도메인 서사.
구현 디테일이나 이벤트명 없이, 기능의 핵심 흐름만 서술.
(관련 RFC/API spec 인라인 링크)

## 비즈니스 규칙
가능/불가/조건/제약을 선언적으로 나열.
- 규칙 1
- 규칙 2
(관련 RFC/ADR 인라인 링크)

## 상태 변화
Before → After 형태로 상태 전이 요약.
조건부 전이가 있다면 명시. 구현 디테일(클래스명, 메서드명) 금지.
(관련 테스트 코드 인라인 링크)
```
