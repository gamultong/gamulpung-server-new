# Feature(FT) 작성 가이드
- `docs/Feature/`에 저장한다.
- 파일 이름은 `[FT-XXX] Title`의 형태로 작성한다.
- 시나리오(Use Case)와 행동(Behavior)을 도메인 관점에서 설명한다.
- 입력/출력은 의미 수준만 적고, 구체 스키마는 각 섹션에 인라인으로 링크한다.
- 핵심 비즈니스 규칙과 상태 변화를 간단히 요약한다.
- API spec, RFC, 테스트 코드 링크는 관련 섹션에 인라인으로 배치한다.

## 형식
```md
# 기능명

## 목적
이 기능(도메인 행동)이 해결하는 문제 또는 존재 이유.

## 시나리오(Use Case)
핵심 흐름을 요약한다.
- UC-1: ...
- UC-2: ...

## 행동(Behavior)
이 기능이 외부에서 어떻게 사용되는지, 어떤 반응을 하는지.
개발 자료가 아니라, 도메인 레벨에서 서술.
(관련 RFC가 있다면 여기 인라인 링크)

## 입력 (Input)
이 행동을 시작하기 위해 필요한 정보의 요약.
(API spec 링크를 여기 인라인으로)

## 출력 (Output)
이 기능 수행 결과로 제공되는 의미적 결과.
(API spec 링크를 여기 인라인으로)

## 비즈니스 규칙(Business Rule)
핵심 규칙(정책, 제약, 계산 로직의 의미적 정의).
(관련 RFC/ADR이 있다면 인라인 링크)

## 상태 변화(State)
도메인 상태가 어떻게 변화하는지 요약.
(관련 테스트 코드가 있다면 인라인 링크)
```
