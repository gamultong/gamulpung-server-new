# Payload 작성 가이드

설계 원칙은 [HR 구현 가이드](/docs/Other/Convention%20guide/HR.md)의 Event payload 절 참고: **현재 상태는 fetch, 과거만 payload**.

## 내부 payload 선택 기준

```python
# 식별자만 필요하면 IdPayload — Receiver가 처리 시점에 최신 상태를 fetch한다
Event(event_name=InternalEvent.NOTIFY_CURSORS, payload=IdPayload(id=new.id))

# 변경 이전 snapshot이 필요하면 IdDataPayload — 과거는 fetch로 복원할 수 없다
Event(event_name=InternalEvent.WINDOW_SET, payload=IdDataPayload(id=new.id, data=old))
```

- 현재 상태를 data에 싣지 않는다. 싣는 순간 전달 시점·순서에 민감해진다.
  ([[ADR-004] 인메모리 우선 인프라 채택](/docs/ADR/%5BADR-004%5D%20인메모리%20우선%20인프라%20채택.md))

## 외부 payload (ClientMessage / ServerMessage)

- external sub-module에 정의하고 [API 명세](/docs/Other/API_spec/WebSocket/README.md)와 동기화한다.
- 클라이언트 입력은 신뢰 경계다. 필수 키·타입 검증이 필요하면 from_dict를 오버라이드한다.

```python
class CreateCursor(ClientMessage):
    width: int
    height: int
    color: int

    @classmethod
    def from_dict(cls, dict: dict):
        if "color" not in dict:
            raise ValueError("CREATE_CURSOR payload에 color가 필요합니다.")

        return cls(
            width=dict["width"],
            height=dict["height"],
            color=int(dict["color"]),
        )
```

- 발신자 id는 payload에 넣지 않는다. 연결 계층이 IdDataPayload로 주입한다.
