# Lifecycle 사용법

원칙은 [[RFC-008] Lifecycle](/docs/RFC/%5BRFC-008%5D%20Lifecycle.md) 참고. 이 문서는 적용 방법만 다룬다.

## Handler 변이 메서드에 적용

표준 5단계 템플릿. `@classmethod`가 위, lifecycle 데코레이터가 아래다.

```python
class CursorHandler:
    @classmethod
    @LifeCycle.with_async_lifecycle(
        factory=HLife.create_factory("CursorHandler", "move")  # 식별자: (Handler명, 메서드명)
    )
    async def move(cls, cursor: Cursor, position: Point) -> None:
        hlife = HLife.get_lifecycle()          # 1. inline에서 현재 lifecycle 접근

        old_cur = await cls.get_by_id(cursor.id)
        new_cur = old_cur.copy()
        new_cur.position = position

        hlife.set_snapshot(before=old_cur, after=new_cur)   # 2. 전이 기록

        await cls.update(new_cur)              # 3. 상태 갱신

        events = CursorEmitter.get_events(old=old_cur, new=new_cur)  # 4. Event 도출
        hlife.add_events(events)               #    발행 Event도 lifecycle에 기록
        for event in events:
            await EventBroker.publish(event=event)          # 5. publish
```

- 식별자 문자열은 메트릭 라벨로 그대로 들어가므로 오타에 주의한다.
- snapshot·Event를 반환값으로 전달하지 않는다. inline 접근이 규칙이다.

## Receiver에 적용

```python
@EventBroker.add_receiver(ClientEvent.MOVE)
@LifeCycle.with_async_lifecycle(factory=RLife.create_factory)
async def move_receiver(event: MOVE_EVENT):
    ...
```

- 등록(broker)이 위, 추적(lifecycle)이 아래 — 17개 receiver 전부 동일하다.
- RLife 컨텍스트 안에서 호출된 Handler의 HLife는 Caller에 자동 등록된다. 별도 코드가 필요 없다.

## Observability

- 메트릭: 데코레이터만 적용하면 LifecycleMetrics가 Prometheus 지표를 자동 수집한다.
- 프로파일: `with LifecycleProfiler() as profiler:` 블록 안의 실행이 기록되며, `to_trace_events()`로 Chrome Trace 형식을 얻는다. (사용 예: /tests/integration/test_lifecycle_profiler.py)
