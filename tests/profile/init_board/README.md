# Init Board 성능 최적화 분석

## 개요

`initialize_start_map` 함수의 성능 병목을 분석하고 최적화한 결과를 정리한 문서입니다.

## 최적화 결과 요약

| 지표 | Before | After | 개선율 |
|------|--------|-------|--------|
| **실행시간** | 2,210ms | 1,452ms | **-34.3%** ⬇️ |
| **CPU User** | 2.220s | 1.290s | **-41.9%** ⬇️ |
| **메모리 Peak** | 65.5MB | 62.5MB | **-4.6%** ⬇️ |

## 병목 분석 (Before)

기존에는 DB호출을 병목으로 보고 이를 1회 호출로 변경하려 했지만, 상수 자체가 작아 이는 8% 밖에 소요하지 않았습니다.
오히려 Tile의 생성 비용이 큰 병목으로 자리잡고 있었습니다.


#### `number_section` 함수 (1.243초 / 56.2%)
- **`Tiles.at_tile`** (0.522초): 타일 조회 작업
  - `from_int` 메서드 (0.350초): int에서 Tile 객체 생성
  - 매우 빈번하게 호출됨
- **`Tile.copy`** (0.172초): 타일 복사 작업
- **셀프 타임** (0.458초): number_section 함수 자체 로직

#### `rand_tiles` 함수 (0.475초 / 21.5%)
- **`Random.randint`** (0.283초): 랜덤 넘버 생성
- **`rand_tile`** (0.394초): 랜덤 타일 생성

#### `numbering_tiles` 함수 (0.291초 / 13.2%)
- **`count_mine`** (0.221초): 주변 지뢰 개수 계산
  - `Tiles.at_tile` 반복 호출 (0.091초)

#### DB 작업 (0.18초 / 8%)
- `create_section` commit: 0.129초
- `update_section_flag` commit: 0.053초
- 상대적으로 작은 비중

## 최적화 전략

Tile 자체가 256가지의 경우의 수 밖에 없고
DataObj가 immutable하여도 되게 설계된 점을 고려하여
**Tile 불변 객체화 + 캐싱**으로 최적화 하였습니다.

### 핵심 변경사항

1. **Frozen Dataclass 적용**: `frozen=True`로 불변 객체화
2. **@cache 데코레이터 추가**: `from_int`, `create` 메서드에 캐싱 적용
3. **with_* 메서드 도입**: 속성 변경 시 캐싱된 새 객체 반환
4. **직접 할당 제거**: `tile.number = x` → `tile.with_number(x)` 패턴으로 변경

## 최적화 효과 분석 (After)

### 주요 개선 지점

#### 1. `Tiles.at_tile` - 극적 개선!
- **Before**: 0.613초 (0.522초 + 0.091초)
- **After**: 0.113초
- **개선**: **-81.6%** 🔥
- **원인**: `from_int` 캐싱으로 객체 생성 비용 절감

#### 2. `Tile.copy` 제거 효과
- **Before**: 0.172초
- **After**: `Tile.with_number` 0.019초
- **개선**: **-89.0%** 🔥
- **원인**: 캐싱된 객체 재사용, 불필요한 복사 제거

#### 3. `number_section` 함수
- **Before**: 1.243초
- **After**: 0.612초
- **개선**: **-50.8%**

#### 4. `count_mine` 함수
- **Before**: 0.221초
- **After**: 0.094초
- **개선**: **-57.5%**

## Tile 객체 생성 비용 분석

### Before: 순수 Tile 생성/복사 비용
- `from_int`: 0.350초
- `copy`: 0.172초
- **총합**: **0.522초** (전체의 23.6%)

### After: 캐싱 적용 후
- `at_tile` (from_int 포함): 0.113초
- `with_*` 메서드: 0.019초
- **총합**: **0.132초**

### 절감 효과
**0.503초 절감** - 이는 전체 성능 개선(0.76초)의 **66%**를 차지합니다.

나머지 개선은 메모리 할당/GC 부담 감소, 캐시 히트로 인한 간접 효과입니다.

## 최적화의 핵심 원리

1. **캐싱**: 동일한 속성을 가진 Tile은 같은 인스턴스를 재사용 (최대 256가지)
2. **불변 객체**: frozen=True로 캐시 안전성 보장
3. **복사 비용 제거**: `Tile.copy()` 대신 `with_*` 메서드로 캐싱된 객체 반환
4. **메모리 효율**: 중복 객체 생성 방지로 메모리 4.6% 감소, GC 부담 감소

## 결론

Tile을 불변 객체로 만들고 캐싱을 적용한 결과, **실행 시간 34.3% 개선**을 달성했습니다.
특히 가장 큰 병목이었던 `Tiles.at_tile` 호출이 81.6% 개선되어 전체 성능 향상에 크게 기여했습니다.

이 최적화는 객체 생성 비용이 높고 가능한 경우의 수가 제한적인 경우,
불변 객체 + 캐싱 패턴이 매우 효과적임을 보여줍니다.
