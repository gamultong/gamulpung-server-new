# 테스트 유틸 사용법

작성 규칙은 [테스트 작성 가이드](/docs/Other/Convention%20guide/Test.md) 참고. 이 문서는 도구 사용법만 다룬다.

## PytestTCM — WebSocket 클라이언트 목

```python
with PytestTCM(app).append_client("TestClient_A") as tcm:
    cl_a = tcm.get_client("TestClient_A")

    cl_a.ws.send_json({...})        # 클라이언트 → 서버 (원시 wire JSON)
    cl_a.conn.send                  # 서버 → 클라이언트 송신을 캡처하는 AsyncMock
```

## ASCII 맵 DSL — build_tiles

첫 줄이 보드의 최상단(y 최대)이다. 닫힌 타일의 number는 인접 지뢰 수로 자동 계산된다.

| 문자 | 의미 |
|---|---|
| `#` | closed (자동 numbering) |
| `.` | open (number 0) |
| `F` | closed + flag (자동 numbering) |
| `X` | closed + mine |
| 숫자 | closed + 수동 number (자동 계산 무시) |

```python
tiles = build_tiles("""\
####
#X##
####
""")
sections = [Section(Point(0, 0), tiles.copy(), flag=SectionFlag.INTERACTIONAL)]
```

## 이벤트 대기 — assert_wait 계열

고정 sleep 대신 폴링 헬퍼를 쓴다. 선택 기준:

- `assert_wait_event(mock, event_name)` — 처리 완료 **대기용**. 검증으로 쓰지 않는다.
- `assert_wait_message(mock, message)` — payload까지 **완전 매칭 검증**. 기본 검증 수단이다.
- `assert_wait_call_if(mock, predicate)` — range 매칭 등 커스텀 조건. 잔여 이벤트와 구분할 때 쓴다.

매칭된 call은 mock에서 **소비(pop)** 되므로, 같은 이벤트를 두 번 검증하려면 두 번 발생해야 한다.

## 커서 위치 고정 — create_cursor_at_position

```python
with patch("data.cursor.Cursor.create", side_effect=create_cursor_at_position(Point(1, 1))):
    ...  # 이 블록 안에서 생성되는 커서는 (1, 1)에 위치
```
